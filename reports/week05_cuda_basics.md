# 第 5 周实验报告：CUDA 编程模型与向量加法 Kernel 优化

## 1. 实验环境与硬件
- **GPU 型号**: NVIDIA GeForce RTX 3060 Laptop GPU (物理理论带宽约 336 GB/s)
- **编译工具**: nvcc 12.0 (-O3 优化)
- **测试数据规模**: 10,000,000 个 float32 (约 38.15 MB)

## 2. 实验核心数据

### (1) CPU vs GPU 基准对比
- **CPU 单核耗时**: 20.65 ms
- **GPU 最优耗时**: 0.405 ms
- **加速比**: **50.99x (约 51 倍)**

### (2) Block Size 对耗时与有效带宽的影响
| Block Size | Grid Size | 耗时 (ms) | 有效显存带宽 (GB/s) | 带宽利用率 |
|---|---|---|---|---|
| 32 | 312500 | 0.565 | 212.22 | 63.16% |
| 64 | 156250 | 0.405 | 295.93 | **88.07% (逼近极限)** |
| 128 | 78125 | 0.451 | 266.34 | 79.27% |
| 256 | 39063 | 0.481 | 249.55 | 74.27% |
| 512 | 19532 | 0.526 | 228.30 | 67.95% |
| 1024 | 9766 | 0.428 | 280.69 | 83.54% |

- **正确性校验**: CPU 与 GPU 输出最大绝对误差为 `0.000000` (严格一致)。

## 3. 核心机制总结
1. **合并访存 (Memory Coalescing)**:
   - 线程全局索引按 `blockIdx.x * blockDim.x + threadIdx.x` 严格连续映射。
   - Warp 内 32 个线程的访存请求被硬件合并为极高效率的连续内存事务，这是达到 296 GB/s 显存带宽的关键。
2. **Block Size 的选择**:
   - 单 Block 设置为 64~256 个线程时综合表现最佳，能够提供充足的活跃 Warp 来隐藏内存访问延迟。
